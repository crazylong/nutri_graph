# 项目启动

把 nutri_graph 在本机跑到能问答。生产机的 systemd / nginx 见 [deploy.md](deploy.md)。

本机要起来的东西：

| 组件 | 作用 | 地址 |
|---|---|---|
| FastAPI（`python app.py`） | 问答、登录、审核接口 | http://localhost:8810 |
| Neo4j 5.26 | 食疗主图 | bolt `localhost:7687`，浏览器 http://localhost:7474 |
| PostgreSQL 16 + pgvector | 用户、候选、记忆、别名 | `localhost:5432` / 库 `nutri_graph` |
| Milvus 2.4（etcd + MinIO） | 实体向量与文档块 | http://localhost:19530 |
| Langfuse 3 | 调用追踪，可关 | http://localhost:3000 |
| 百炼 DashScope | 对话与 embedding | 需 `DASHSCOPE_API_KEY` |

图谱问答依赖 Neo4j、PostgreSQL 和百炼。Milvus 或 Langfuse 没起来时，`/health` 会报 `degraded`，图查询本身仍可用，只是没有向量兜底和追踪。

## 前置

- Docker（带 Compose）
- Python 3.11 及以上（远端部署用的是 3.14）
- 阿里云百炼 API Key（[控制台](https://bailian.console.aliyun.com/)）

Milvus + Langfuse + ClickHouse 一起比较吃内存，本机建议 8 GB 以上空闲内存。只想先通图谱问答时，仍建议整份 `docker compose up -d`，等健康检查过了再往下走。

## 1. 起依赖

在仓库根目录：

```bash
docker compose up -d
docker compose ps
```

`neo4j`、`postgres`、`milvus`、`langfuse` 都变成 healthy 再继续。Milvus 和 Langfuse 第一次拉镜像、做初始化，常常要一两分钟。

本机 compose 写死的口令（`docker-compose.yml`）：

| 服务 | 连接 |
|---|---|
| Neo4j | 用户 `neo4j`，密码 `nutrigraph-dev` |
| PostgreSQL | `postgresql://nutri:nutri@localhost:5432/nutri_graph` |
| MinIO | `minioadmin` / `minioadmin`，控制台 http://localhost:9001 |

`config.py` 在没读到 `.env` 时用的就是这两条库口令。`.env.example` 里的 `NEO4J_PASSWORD` 和 `PG_DSN` 是另一套环境的值，抄过来会在装种子数据时直接 `AuthError`。

## 2. Python 环境

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

短信通道用 `console` 时不用装阿里云 SDK。改成 `dypns` 再取消 `requirements.txt` 里 `alibabacloud_dypnsapi20170525` 那一行的注释并重装。

## 3. 配置 `.env`

```bash
cp .env.example .env
```

本机至少改这几项：

```dotenv
DEBUG=true
AUTH_REQUIRED=false
SMS_PROVIDER=console

NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=nutrigraph-dev
PG_DSN=postgresql://nutri:nutri@localhost:5432/nutri_graph

DASHSCOPE_API_KEY=你的百炼key
```

`DEBUG=true` 有两个效果：验证码会回填到 `/auth/sms` 的响应里，并且 `python app.py` 会开热重载。对外服务必须保持 `DEBUG=false`。

暂时不用 Langfuse 时设 `LANGFUSE_ENABLED=false`。要用的话，打开 http://localhost:3000 注册一个项目，把 Public / Secret Key 填进 `LANGFUSE_PUBLIC_KEY` 和 `LANGFUSE_SECRET_KEY`。Key 留空时追踪会自动跳过，服务照常启动。

本机 `AUTH_REQUIRED=false` 时，`/chat` 可以不登录，用请求体里的 `user_id`。要练登录流程再配下面三个，三者互相独立：

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

分别写入 `JWT_SECRET`、`PHONE_ENC_KEY`，再另给一个 `PHONE_HASH_PEPPER`。Pepper 一旦有了真实用户就不要再改，改了已注册手机号都对不上。

## 4. 初始化数据

下面每条都可以重复执行。

```bash
python -m scripts.migrate --status
python -m scripts.migrate
python -m kg.constraints
python -m scripts.load_crosswalk
python -m scripts.load_seed
```

- `migrate` 按 `migrations/001` … `008` 建身份、业务、记忆向量、补录和审核表。本机 `nutri` 就是该库的超级用户，`CREATE EXTENSION vector` 能在迁移里直接成功。
- `constraints` 给 Neo4j 的 `canonical_id` 加唯一约束。
- `load_crosswalk` 把 `data/crosswalk/` 写入 PostgreSQL 的 `dict_alias`（约 360 条别名）。
- `load_seed` 把演示图写入 Neo4j（约 125 个节点、40 条边）。

有了百炼 Key、并且 Milvus 已 healthy 之后，把别名索引进向量库，实体链接的向量兜底才有数据：

```bash
python -m scripts.index_entities --dry-run
python -m scripts.index_entities
```

## 5. 启动 API

```bash
python app.py
```

- 接口：http://localhost:8810
- OpenAPI：http://localhost:8810/docs
- 模型池：http://localhost:8810/llm/pool

`app.py` 只挂 API，不提供页面。`frontend/` 里的页面用相对路径请求 `/chat`、`/auth`，本地直接用浏览器打开 `index.html` 会对到错误的源。本机调试用 `/docs` 或下面的 curl。页面和反代的接法见 [deploy.md](deploy.md)。

## 6. 验收

```bash
curl -s http://localhost:8810/health
```

Neo4j、PostgreSQL、Milvus 都 `ok` 时 HTTP 200、`status` 为 `ok`。有一项失败则 503、`status` 为 `degraded`，响应里的 `checks.*.error` 会写出原因。

```bash
curl -s -X POST http://localhost:8810/chat \
  -H 'Content-Type: application/json' \
  -d '{"question":"痛风能吃海鲜吗","user_id":"u1"}'
```

看三个字段：`answer`、`graph_hit`（这次是否真走了图谱）、`evidence_counts`。

模型池：

```bash
python -m scripts.check_llm_pool
python -m scripts.check_llm_pool --probe
```

登录链路（`DEBUG=true` 时响应里带验证码）：

```bash
curl -s -X POST http://localhost:8810/auth/sms \
  -H 'Content-Type: application/json' -d '{"phone":"13800138000"}'
```

进程内自检（不占 8810）：

```bash
DEBUG=true python -m scripts.auth_smoke --in-process
```

## 再次启动

数据卷还在的话，不用重跑迁移和种子：

```bash
docker compose up -d
source .venv/bin/activate
python app.py
```

改过 `.env` 后重启进程即可。`DEBUG=true` 时改 Python 代码会自动重载。

停依赖、保留数据：

```bash
docker compose down
```

`docker compose down -v` 会删掉 Neo4j、PostgreSQL、Milvus 的卷，下次要重做第 4 步。

## 卡住时先看这里

**Neo4j `AuthError`。** `.env` 的 `NEO4J_PASSWORD` 和容器里的 `NEO4J_AUTH` 不一致。本机应对齐 `nutrigraph-dev`。容器已经用别的密码初始化过数据卷时，改 compose 不会改掉旧密码，要对齐已有卷里的口令，或删掉 `neo4j_data` 卷后重建。

**PostgreSQL 连不上或没有 `vector`。** 确认 `PG_DSN` 是 `postgresql://nutri:nutri@localhost:5432/nutri_graph`，并且 `docker compose ps` 里 `postgres` 是 healthy。迁移失败时按 `scripts.migrate` 打印的提示处理；本机镜像是 `pgvector/pgvector:pg16`，扩展在镜像里。

**`/health` 里只有 Milvus 红。** 等 `nutri_milvus` healthy，或接受降级继续用图谱。实体向量索引要等 Milvus 好了再跑 `index_entities`。

**问答 500 或答不出来。** 先看 `DASHSCOPE_API_KEY`，再跑 `python -m scripts.check_llm_pool --probe`。池里模型额度用尽会被移出，补额度后执行 `python -m scripts.check_llm_pool --reset`。

**验证码看不到。** `SMS_PROVIDER=console` 不发短信。`DEBUG=true` 时看接口响应里的 `dev_code`；`DEBUG=false` 时验证码只在进程日志里，用 `python -m scripts.latest_code --phone 13800138000`。

**测试把演示数据清掉。** `pytest` 会清空业务表，默认只在库名含 `test` 时放行。对本机演示库跑测试前先看 README 里「测试」一节，需要单独的 `nutri_graph_test`，或显式 `TEST_DB_OK=1`。
