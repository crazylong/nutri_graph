# 技术细节

> 对照当前代码。配置默认值以 `config.py` 为准，环境变量可以覆盖。流程级叙述见 [数据流程.md](数据流程.md)，图模式见 [neo4j建表细节.md](neo4j建表细节.md)，向量集合见 [milvus索引细节.md](milvus索引细节.md)。

## 1. 证据模型

证据挂在**关系**上，两层正交，不互相推导。

| 维度 | 取值 | 含义 |
|---|---|---|
| `evidence_type` | `guideline` / `measured` / `traditional` / `anecdotal` | 这是哪一类证据 |
| `evidence_level` | `A` / `B` / `C` / `D` | 多可信 |

配套字段：

- `sources`：出处列表。PostgreSQL 用 JSONB；写入 Neo4j 前必须 `kg.schema.sources_to_json`，因为 Neo4j 属性不接受 map。
- `claim_text`：原始断言，生成时引用、评估时回溯。
- `confidence`：0–1，排序用，不代替证据等级。
- `provisional`：人工已通过，但来源数小于 `FOOD_TRUSTED_MIN_SOURCES`（默认 2）。单源实测封顶 `PROVISIONAL_EVIDENCE_LEVEL`（默认 `C`），多源才给 `TRUSTED_EVIDENCE_LEVEL`（默认 `B`）。补录到不了 `A`。

各意图默认允许的 `evidence_type`（`EVIDENCE_POLICY_MAP`）：

| 意图 | 默认放行 |
|---|---|
| `pair` 搭配 | guideline, measured, traditional |
| `incompatible` 不宜同食 | 上面三种 + anecdotal |
| `contra_population` / `contra_item` / `nutrition` / `symptom_remedy` | guideline, measured |
| `substitute` | guideline, measured, traditional |

不宜同食把民间说法放进来，靠等级降档，而不是在检索层直接丢掉。医学向的禁忌和营养只留 guideline 与 measured。

`INCLUDE_PROVISIONAL` 默认 `true`：刚审核完的单源边能被查到，上下文标成 `[measured/C·单源]`。设成 `false` 时，每条 Cypher 模板里的条件会排除 `provisional=true` 的边。

## 2. 节点与关系（查询侧）

五类节点：`Ingredient`、`Nutrient`、`Population`、`Symptom`、`Taboo`。

七类关系及方向（无向语义的搭配/相克在 Cypher 里用无方向匹配）：

| 关系 | 方向 | 额外属性 |
|---|---|---|
| `CONTAINS_NUTRIENT` | 食材 → 营养素 | `amount` `unit` `per` |
| `RECOMMEND_PAIR` | 食材 — 食材 | `effect` `rationale` |
| `INCOMPATIBLE_WITH` | 食材 — 食材 | `reason` `severity` |
| `CONTRA_POPULATION` | 食材 → 人群 | `condition` |
| `SUBSTITUTE_FOR` | 食材 → 食材 | `basis` `similarity` |
| `CONTRA_ITEM` | 食材 → 禁忌对象 | `interaction` |
| `HAS_SYMPTOM` | 人群 → 症状 | `relation` |

民间说法落 `INCOMPATIBLE_WITH`。人群医学禁忌落 `CONTRA_POPULATION`，药物或疾病状态落 `CONTRA_ITEM`。症状问法没有「对症推荐吃什么」的边：`symptom_remedy` 从症状走到关联人群，再走到这些人该避开的食材。

`canonical_id` 形如 `ING_00001`。前缀：`ING` / `NUT` / `POP` / `SYM` / `TAB`，序号五位。补录序列 `ingredient_cid_seq` 从 1000 起，所以补录食材是 `ING_01000` 往后，和种子 `ING_00001`–`ING_00125` 一眼能分开。

关系业务键：

```text
relation_key = sha1(f"{src_cid}|{rel}|{dst_cid}")
```

Neo4j 没有关系唯一约束，MERGE 锚在 `relation_key` 上。同一对节点同一种关系重复合并不会长出第二条边。

## 3. 实体链接

`kg/normalize.py` 的 `EntityLinker`，由 `graph/nodes.py` 的 `link` 节点调用。

文本先做 `normalize_text`：NFKC、去首尾空白、去掉全部空白。别名表 `dict_alias` 在进程内缓存一份；改完表要重启，或把模块级 `_alias_store` 置空。

整句走 `link_question`：

1. 别名按长度倒序。
2. 在归一化问句里找子串，已被更长别名占用的区间跳过。
3. 同一 `(label, canonical_id)` 只留第一次。
4. 没被占用的字符拼成 `residual`。

`residual` 再交给 `kg.request.extract_candidates` 抽词。每个候选词走 `link()`：

| 顺序 | 方法 | 命中条件 |
|---|---|---|
| 1 | `exact` | `alias_norm` 全等 |
| 2 | `fuzzy` | `kg/textsim.char_similarity` ≥ 0.88 |
| 3 | `vector` | Milvus `kg_entity` 首条 `distance` ≥ `ENTITY_LINK_THRESHOLD`（默认 0.82） |
| 4 | 未命中 | 进入 `unresolved`，并用相似度 ≥ 0.62 产生 `near_misses` |

向量检索在 `link` 节点里包了一层：Milvus 或 embedding 失败只打日志并返回空列表，整次问答继续。`ENTITY_LINK_TOP_K`（默认 5）目前没有接到调用点，`link()` 写死 `top_k=3`。

中文模糊不用 `pg_trgm`。`similarity('黑大豆','黑豆')` 实测为 0。`pg_trgm` 索引仍建在 `dict_alias.alias_norm` 上，留给英文名和拼音；`AliasStore.trigram_lookup` 保留，中文主路径是 `fuzzy_lookup`。

`dict_alias_candidate` 记录「像某个已有节点的新说法」。冲突时只在 `status=pending` 时更新建议；已批准或已驳回的行不被后来的启发式覆盖。

## 4. 意图与查询计划

`detect_intent` 用关键词子串，命中多个就都保留，一个都没命中则默认 `pair`。

`plan_queries` 把意图绑到节点标签上再发查询：

| 意图 | 锚点必须是 |
|---|---|
| `pair` `incompatible` `contra_population` `contra_item` `nutrition` `substitute` | `Ingredient` |
| `symptom_remedy` | `Symptom` |

食材 id 不会拿去套症状模板。对得上才进 `graph_query`；对不上且 `unresolved` 非空进未收录；否则降级向量。

每条模板都带：

- `r.evidence_type IN $allowed`
- 食材—食材类关系还有 `NOT b.canonical_name IN $allergens`（画像里的 `allergies` + `avoid_list`）
- `($include_provisional OR coalesce(r.provisional, false) = false)`
- `ORDER BY r.evidence_level`（字母序 A 在前），部分模板再按 `confidence DESC`
- `LIMIT $k`，`k = GRAPH_MAX_RESULTS`（默认 8）

查询结果带回 `intent`、`_src_cid`、`_src_label`、`_src_name`，供前端把边挂回问句里的那个食材。

## 5. 生成边界

`graph/boundary.py` 把图结果分成三档：

| 档 | 条件 | 生成约束 |
|---|---|---|
| `strong` | 至少一条 A 或 B | 正常回答并列出依据 |
| `weak` | 只有 C 或 D | 必须写明未经充分验证 |
| `none` | 没有图事实 | 固定弃答，不给具体建议 |

全部事实都是 `provisional` 时，即使等级被标成 A/B，档位也降到 `weak`，提示语用 `PROVISIONAL_DISCLAIMER`（单一来源、已人工审核、未交叉验证），不用「传统经验或民间说法」那句。

另外两条固定话术：

- 图 0 命中且向量块也没有，但食材已经链接上：说明「已收录，缺这方面的证据」，避免用户以为没入库再登记一次。
- 食材也没链接上、向量也空：`NONE_ANSWER`（没有找到确切依据）。
- 图 0 命中、向量分数 ≥ `CHUNK_THRESHOLD`（默认 0.40）：文档转述，回答里要说明不是图谱结论。低于阈值的块在 `vector_fallback` 里丢掉，不会进提示词。

提示词要求模型只依据给定事实，返回 JSON：`answer` / `basis` / `gaps` / `confidence`。解析失败就把原文当 `answer`。

模型池全部不可用时，`generate` 返回「暂时答不了」，不编造。没配 `DASHSCOPE_API_KEY` 时走占位回答，便于骨架验收。

近期对话从 `ShortTermMemory.load_context` 读入提示词，注释写明只帮助理解指代，不当成图谱事实。没有 `session_id` 时不读，避免串会话。

## 6. 子图返回

`/chat` 在 `graph_hit=true` 时附带 `facts` 和 `subgraph`。`kg/subgraph.py` 把扁平查询行翻译成：

```text
nodes: [{id, label, name, anchor, hop, props}]
edges: [{source, target, rel, rel_label, evidence_type, evidence_level,
         claim, detail, amount, unit, provisional, hop, path}]
```

关系中文名集中在这一处（含有、推荐搭配、不宜同食、人群禁忌、可替代、禁忌事项、关联症状）。

探索接口不走生成：

- `GET /kg/subgraph` → `neighborhood`。默认 1 跳；`depth=2` 时只再展开最多 `SUBGRAPH_DEPTH2_SEEDS`（默认 4）个一跳食材。
- `GET /kg/relation` → 先查直接边，没有再 `shortestPath`，跳数上限 `SUBGRAPH_MAX_HOPS`（默认 3，代码里再夹到 1–4）。
- 点数上限 `SUBGRAPH_MAX_NODES`（40），边数上限 `SUBGRAPH_MAX_EDGES`（60），超出标截断。

补录的营养数值有时只写在 `claim_text` 里。`parse_amount` 从断言文本回捞最后一个「数字 + 单位」（前面的「每 100g」不是含量）。关系上若已有 `amount`，以关系属性为准。

## 7. 模型池

业务调用 `llm.invoke_model`。切换用 LangChain `AgentMiddleware.wrap_model_call`：失败时 `request.override(model=下一个)` 交给官方 handler 重试。需要原生 `BaseChatModel` 回退链的场合（评估、画像抽取）用 `pool_chain()`，即 `head.with_fallbacks(rest)`。

池成员只来自 `LLM_MODEL_POOL`，逗号分隔，顺序即优先级。`LLM_MODEL` 是池外兜底。

| 失败 | 处置 |
|---|---|
| 403 额度用尽（`AllocationQuota` / `insufficient_quota`） | 移出池，状态写入 `data/llm_pool_state.json`。`python -m scripts.check_llm_pool --reset` 才回来 |
| 429 / 5xx / 超时 / 模型不存在 | 冷却。限流默认 60 秒，模型无效默认 24 小时 |
| 401 / 400 | 不切换，直接抛 |

成功的模型会粘住，避免同一进程里来回换导致 JSON 结构抖动。推理模型把 completion 预算花在 reasoning 上、`content` 为空时，中间件把 `max_tokens` 抬到 `LLM_MAX_TOKENS_CEILING`（默认 8192）重试一次。

默认温度 0.2，超时 90 秒，普通 `max_tokens` 2048。评估时 faithfulness 的 statement 生成必须用 ceiling，否则会被截断。

Embedding 与对话模型分开：`text-embedding-v3`，1024 维，OpenAI 兼容端点。`OpenAIEmbeddings` 必须 `check_embedding_ctx_length=False`，否则 langchain-openai 会把文本先切成 token id，DashScope 返回 `contents is neither str nor list of str`。

## 8. 未收录、抓取、打分

登记三出口，顺序固定（`kg/request.py`）：

1. 不是食材（症状、人群、营养素、乱码）→ 拒绝，不进队列。
2. 与已知别名字级相似度 ≥ `FOOD_NEAR_MISS_MIN_SIM`（0.62）→ 写 `dict_alias_candidate`，回答里反问。
3. 否则写 `kg_ingredient_request`。`food_key` 是归一后的中心词（黑豆粥 / 炒黑豆 → 黑豆），唯一，重复问只加 `hit_count`。

每人每天新条目默认 10，全站每天 200。一句话里 `uncatalogued` 节点最多登记 2 个词。

抓取不在 `/chat` 里。`python -m scripts.run_fetch`：

```text
claim → 检索画像 → USDA 搜索 → 同名异物核对 → 拉详情 → verify → 落 bundle
```

同名异物不看 `foodCategory`。黑豆（Glycine max）和黑菜豆（Phaseolus vulgaris）在 USDA 里同属豆类，SR Legacy 还经常不返回 `scientificName`。判据是画像上的两个词表：

- `identity_keywords`：描述里必须出现（黑豆 → `soybean`）
- `exclude_keywords`：出现即否决（`black` / `turtle` / `mung` 等）

在通过词表的候选里，SR Legacy +0.2，描述含 `raw` +0.1，学名属名出现 +0.2。

`kg/verify.py` 的分数是加权和，不是四个因子相乘（模块顶部注释里的乘号是笔误，实现是加法）：

```text
score = 完整性×0.20 + 权威性×0.30 + 一致性×0.30 + 无冲突×0.20
```

| 维 | 算法 |
|---|---|
| 完整性 | 必需字段 `canonical_name` / `english_name` / `category` 占 0.6，营养素至少 4 项占 0.4。缺字段或缺营养素同时构成硬否决 |
| 权威性 | `usda_fdc` 与 `china_fcd` 为 1.0，`web` 为 0.3，白名单外为 0 并硬否决 |
| 一致性 | 来源数 ≥ 2 为 1.0，否则恒 0.6 |
| 无冲突 | 与既有别名冲突则为 0，并硬否决 |

理想单源（四维都满分、一致性 0.6）得 0.88，低于 `FOOD_AUTO_APPROVE_MIN_SCORE`（0.9），并且来源数也低于 `FOOD_AUTO_APPROVE_MIN_SOURCES`（2），所以 USDA 单源必然 `pending_review`。硬否决同样进人工，不会自动写图。

任务领取用 `FOR UPDATE SKIP LOCKED`。`running` 超过 15 分钟可由 `--recover` 退回 `queued`。每日预算默认 50 个任务。同一 `food_key` 只有一个任务，同一 `request_id` 只有一份 bundle，重跑覆盖。

FDC 只拉 `Foundation,SR Legacy`，不要 Branded。默认 `DEMO_KEY` 是 30 次/小时、50 次/天的共享钥匙。

## 9. 审核翻译与合并

`kg/promote.approve_bundle` 只做翻译：

- 先查 `dict_alias`，再查已审核的 `kg_node_candidate`。命中则挂到既有 `canonical_id`（`identity=existing_alias`），不新建。
- 否则 `nextval('ingredient_cid_seq')`，格式化成 `ING_` + 五位。先查后分配，merge 失败重试不重复占号。
- 节点候选 `props` 进图时再过 `NODE_PROPS_WHITELIST`。`Nutrient` 不写 `provenance`：蛋白质这类共享节点不能在回滚某一批时被删掉。
- 别名在 merge 成功之后写入 `dict_alias`。名字已被别的节点占用就跳过并记日志。
- 非 provisional 的食材才会 `insert_entity` 进 Milvus。单源节点不进向量库，避免 Cypher 的 provisional 过滤被向量兜底绕开。

`kg.merge`：

1. `merge_nodes`：按标签分组，`UNWIND` + `MERGE` on `canonical_id`，`SET n += props`。
2. `merge`：跳过 `dst_id` 为空或 `UNRESOLVED` 的边；`MERGE` on `relation_key`；`sources` 写成 JSON 字符串；`review_status='merged'`。
3. 候选行状态改为 `merged`。

`rollback(batch_id)` 删除 `r.batch_id` 等于该批的边，再 `DETACH DELETE` 属性 `provenance` 包含该 `batch_id` 的节点。挂到旧节点上的食材不会被删。候选状态退回 `pending`。

种子装载不走这张候选表，但 MERGE 键相同。

## 10. 表格导入

模板 v1 是宽表，一行一个食物。解析在 `kg/importer.py`（大小与行数上限在这里）。公开接口三道闸：单文件大小、单文件行数、每 IP 每天 `FOOD_IMPORT_DAILY_LIMIT_PER_IP`（默认 20）。预览默认 60 分钟内可提交（`FOOD_IMPORT_PREVIEW_TTL_MIN`）。

批次表现在叫 `kg_import_job` / `kg_import_row`（012 建的 `demo_*` 由 013 改名）。行裁决：`ok` / `warn` / `error` / `duplicate_file` / `duplicate_db`。

提交后进 `kg_food_bundle`，`source_key='excel_import'`，`evidence_type` 固定写成 `measured`，`source_count=1`，状态直接是 `pending_review`。列本身留给审核透传，导入路径不按行改类型。同一 `food_key` 在 `draft` / `pending_review` / `approved` 上有部分唯一索引，重复上传更新已有未结 bundle，不堆第二份。`demo_food` 已删除，导入数据没有第二条展示库。

## 11. 记忆

| 层 | 实现 | 问答里怎么用 |
|---|---|---|
| 短期 | `session` + `message`，最近 `SHORT_TERM_WINDOW`（10）轮 | 进入提示词，只作指代 |
| 滚动摘要 | `SESSION_SUMMARY_THRESHOLD`（30） | 超长会话摘要字段 |
| 画像 | `user_profile`：过敏、慢病、忌口、饮食风格，以及 010 补的年龄、性别、身高、体重、爱好、症状 | 过敏和忌口进 Cypher；其余进提示词约束。`consent=false` 不读不写 |
| 事实向量 | `memory_fact.embedding vector(1024)` | 表在，`LongTermMemory` 能插入和按用户查出，生成节点不调用 |

画像抽取在 `memory_write` 之后另起守护线程，且只有问句命中健康约束关键词才跑。失败只记日志。

会话归属在进 LangGraph 之前检查：`ShortTermMemory.owns(user_id, session_id)` 失败返回 404，别人的 `session_id` 不会被读进提示词。

回答卡片（证据计数、子图、依据、登记结果、免责声明）和消息一起写入 `message.meta`，历史回放能把图画回来。旧消息没有子图时，`retrieve_card` 只重跑检索、不调生成。

## 12. 身份与短信

| 项 | 默认 |
|---|---|
| access TTL | 1800 秒 |
| refresh TTL | 7 天 |
| 验证码 | 6 位，300 秒，同号最小间隔 60 秒 |
| 同号 | 5 次/时，10 次/天 |
| 同 IP | 10 次/时 |
| 同设备 | 10 次/天 |
| 全局熔断 | 200 次/天 |
| 校验失败 | 手机号连续 5 次锁 15 分钟；IP 累计 50 次才锁 |

refresh 的两种吊销：

- `replaced_by` 有值：被旋转换掉。再用旧票视为重放，吊销整族。
- `replaced_by` 为空且 `revoked_at` 有值：登出。提示重新登录，不当成异常登录。

图形验证码：同一 IP 免费发送次数默认 1，之后要先过 `GET /auth/captcha`。答案存 HMAC，5 分钟，单个 challenge 最多 5 次，答对即消费。

`JWT_SECRET` 为空时进程启动会用一次性随机密钥，重启后全部令牌失效。生产必须显式配置，且建议不少于 32 字节。

## 14. 日志

`utils/logging_config.py` 把根日志写到项目根目录 `logs/`（可用 `LOG_DIR` 覆盖），按午夜切分，默认保留 14 天。`app.py` 启动时会明确打出：鉴权开关、短信通道、JWT 过短、console 通道但 `DEBUG=false`（验证码只在日志）、dypns 缺凭据或缺 SDK。

## 15. 测试约定

pytest 会清空一批业务表。默认仅当库名含 `test` 时放行，否则跳过。确认可以清演示库时设 `TEST_DB_OK=1`。Neo4j 和 `dict_alias` 不在 TRUNCATE 范围内，对着有数据的库跑会留下「图还在、审计行没了」的状态。

连不上 PostgreSQL 或 Neo4j 的用例跳过，不把整组打红。`DEBUG=true python -m scripts.auth_smoke --in-process` 是不占端口的登录链路自检。
