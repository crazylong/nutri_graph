## 3. P1

### 3.1 关掉开关的分支，一条测试都没有

§五 step 4 写「开关为假时，把当前列表切到 `KB_SEARCH_LIMIT`」。这是本期唯一一条**新增的截断逻辑**（原先的截断在 `rerank.py` 里，要删掉），但 §六 的五条用例全在 `diversify()` 函数级，没有一条走 `_retrieve` 的这条路。

同时 `test_search_limit_follows_config` 改完之后桩返回 `[]`，「接口返回不超过 `KB_SEARCH_LIMIT`」这句在自动化里就彻底失守了——需求 4.1 特意强调了这句，反而没测。

建议补一条（几行）：

```
_retrieve + KB_DIVERSIFY_ENABLED=False + 桩 search_question 返回 20 条互不相似的正文
→ 断言 len(hits) == KB_SEARCH_LIMIT，且是原顺序前 6 条
```

顺带把 `test_search_limit_follows_config` 的桩从 `[]` 改成 10 条互不相似的正文，一条用例同时锁「取多少」和「回多少」，比现在只 spy 一个 `limit` 值信息量大。

### 3.2 `diversify` 没有兜底，会把整条文本问答打挂

检索和精排都有兜底：`_rerank` 包了 try/except 并 `log.warning`（`kb/workflow.py:100-108`），`rerank.rerank` 内部每种失败也都退回原顺序。收敛是这期新加到**同一条主路径**上的纯本地步骤，plan 里没有写失败怎么办。

现实里触发点不少：`hits` 里混进非 dict、`text` 是 `list`（Milvus 字段类型漂了）、某条 `text` 是 `None`——plan 的 `(hit["text"] or "")` 能挡住 `None`，挡不住前两种。一旦抛出，`/kb/ask` 与 `/kb/ask/stream` 全部文本提问直接 500，而今天这些请求是能答的。这是「新增一步换掉全部文本问答」的量级，不是边角。

建议 §五 加一句：`_diversify()` 与 `_rerank()` 同构，try/except + `log.warning("收敛异常，退回排序后的前 N 条：%s", exc)` + 返回 `hits[:KB_SEARCH_LIMIT]`。这样最坏情况退化成今天的行为。

### 3.3 `0.72` 挡不住「模板句只差数字」

§四 只说了 `0.72` 用来「去掉大段重复」，没有标定依据。算一下这个阈值意味着什么：Ochiai 形式下 `0.72` 表示两边**七成以上的二字组合相同**，等长文本相当于只改了不到三成的字。对「同一段被复制到两篇文档」这种场景很稳，但它对下面这类正文是失效的：

```
市内交通费：一线城市每人每天 100 元，二线城市每人每天 80 元。
市内交通费：一线城市每人每天 120 元，二线城市每人每天 90 元。
```

两条只差几个数字，二字组合集合差 4～6 个、共二三十个，相似度 ≈ 0.85～0.9 → 判成同一条，**静默丢掉一条真实不同的标准**。这正是 needs 2.2 里「不要把同一章里各讲一件事的段落并掉」的反例，而制度/报销/限额类文档恰恰大量是这种句式：套话相同、数字不同。

两条建议，成本都很低：

1. **加一条不用模型调用的护栏**：抽出两条正文里的数字串（`\d+(?:\.\d+)?`），多重集不同就不合并。数字是这类正文里信息密度最高的部分，用规则挡比调阈值准。
2. **§七 验收补一条真数据核对**：拿一篇含数字表格的文档（`data/` 里就有样本），把它的块两两过一遍 `diversify`，人工看被合掉的都是真重复。只要不进 Milvus、不调模型，这一步是纯本地脚本，几分钟的事。

这两条不写，§六 的合成用例全绿也说明不了默认值在生产语料上是否合适。

## 4. P2

### 4.1 精排只回部分名次时，补不了位

§五 写了「解析后一条都没有 → 返回原 `hits`」，没写「只回了 5 条」这种情况。而现有桩正好是这个形状：8 条候选只回 `index` 3 和 1（`tests/test_kb_v13.py:287-292`）。改完之后这个函数会**返回 2 条**，剩下 6 条就此消失，收敛只能在 2 条里挑——本期要解决的形态原样复现。

线上 `top_n == len(documents)` 时通常全量返回，风险不高，但兜底只要一行：`ordered` 走完后，把没出现在 `index` 里的候选按原顺序追加，再整表返回（分数沿用原 `score`，反正下面只用顺序）。同时 §五 那条「返回顺序按桩的名次」的断言应该改成「用全量桩断言 8 条、用部分桩断言 2+6 补齐」，别把部分返回当成正常形态固化进用例。

### 4.2 `500` 字窗口和 `KB_CHUNK_CHARS` 隐性耦合

§四 沿用精排的 `_DOC_CHARS = 500`。眼下 `KB_CHUNK_CHARS = 480`（`config.py:103`），500 等于全量比较，没毛病。但这是巧合：谁把 `KB_CHUNK_CHARS` 调到 600，前 500 字相同、后 100 字不同的两块就会被并掉，而且不报错。

收敛本来就是纯本地、无模型调用，20 条 × 480 字的集合运算可以忽略不计，**直接比全文**更安全，也不用再维护一个和切块大小耦合的常量。精排那边维持 500 没问题（那是给模型省钱），两处别共用同一个理由。

### 4.3 空白没归一

二字组合把空格、换行也算成组合。PDF 解析出来的同一句话换行位置不同（`差旅费\n报销` vs `差旅费报销`），相似度会掉一截。长文本里影响小，100 字以内的块可能从 0.78 掉到 0.6 以下——该合的没合，正是本期要治的问题。

建议 §四 补一句：切二字组合前先把 `\s+` 压掉（`re.sub(r"\s+", "", text)`）。顺带把全角/半角标点也归一，成本一样。

### 4.4 `span` 会插一行 `llm_call_log`

needs 2.3 写「收敛不写进 LLM 账本」。而 `llm/usage.py:289-306` 的 `span` 在退出时无条件 `_insert(...)` 一行（token 全 0），`kb_rerank` 现在就是这么留痕的。

如果「不进账本」只指不计 token、不参与成本统计，用 `span` 没问题；如果连行都不想要，就得换成 `log.info`。plan 里应写明是哪一种——施工的人按「不加模型调用」实现成 `span`，评审又拿 needs 那句来对，会来回改。我的意见是**继续用 `span`**：验收要靠 `kb_diversify` 这个 span 看输入输出（§七 第一条），和 `kb_retrieve` / `kb_rerank` 保持一致比省一行日志重要。

### 4.5 测试命令缺 `PG_DSN`

§六 只写「库用 `nutri_graph_test`」。但 `tests/test_kb_ask.py` 是 `pytestmark = requires_pg`（该文件第 11 行），不带 `PG_DSN` 时整文件 skip，最后输出「passed」而那条断言根本没跑。

按项目惯例把命令写全（和 memory 里那条一致）：

```bash
PG_DSN='postgresql://nutri:%21Jbgsn%402o26%26@localhost:5432/nutri_graph_test' \
/opt/envs/nutri/bin/python -m pytest -q \
  tests/test_kb_v14.py \
  tests/test_kb_v13.py::test_rerank_reorders_and_failures_cut \
  tests/test_kb_ask.py::test_search_limit_follows_config
```

跑完顺手看一眼 `-rs`，确认没有 `skipped`。

### 4.6 `rerank.py` 的 docstring 会变成假话

模块头写「失败就退回混合检索的原顺序，并截到提问条数」（`kb/rerank.py:1`），函数 docstring 写「返回条数不超过 `KB_SEARCH_LIMIT`」（`:17`）。改完之后这两句都是错的，而且错在「谁负责截断」这个本期最核心的分工上。§三 的改动表把这两行一起列进去。

### 4.7 `KB_RERANK_CANDIDATES` 的语义和钳制

这个变量从今天起不再只是「精排候选数」，而是「文本提问的召回条数」（精排关着也按它取）。名字不改也行，但 `config.py:111-113` 的注释和 README:50 那句「企业知识库文本提问精排」下都要补一句，否则下一个人不敢动。

另外配错方向时会静默降级：`KB_RERANK_CANDIDATES=3`、`KB_SEARCH_LIMIT=6` 时，池子只有 3 条，答案永远最多 3 条依据，不报错。在 `_retrieve` 里取 `max(KB_RERANK_CANDIDATES, KB_SEARCH_LIMIT)` 即可。

### 4.8 图片行算不算收敛对象

plan 的算法对 `hits` 一视同仁，图片行（`block_kind == "image"`，`text` 是 VLM 摘要，见 `kb/publish.py:232-253`）也会参与比较。同一张图的两行已经被 `_dedupe` 按 `image_path` 收掉了，所以收敛在这里只会合并**不同图但摘要相近**的条目。

needs 2.4 只说「不改按 `image_path` 去重」，没说图片行豁免。按字面执行是对的，但要在 §二 与 §七 各写一句：一是声明图片行同样参与；二是验收时确认「一张图被判定近义丢掉时，丢掉的是摘要重复的那张，不是唯一的那张」。这类问题人眼最容易漏，和第 3.3 条的真数据核对可以一起做。

## 6. 附录：收敛方案的实测与开源对照（2026-11-03 补）

> 为回答「代码去重够不够准 / 精排能不能去重 / 有没有现成开源方案」做的实验与调研。实验对象：`data/testdata/` 11 篇真实文档，切出 294 个 ≥80 字的块，两两 43071 对；纯 stdlib 计算，未连库、未调模型。

### 6.1 二字组合的分辨力

| 情形 | 二字组合分 | 标点+空白归一后 | 该不该合 |
|---|---|---|---|
| 长块只改标点/空白（480 字） | 0.89～0.92 | **1.000** | 该合 |
| 短块真重复 | 0.872 | 0.917 | 该合 |
| 代码块只差标识符（`FOR (n:Food)` / `(n:Recipe)`） | 0.883 | 0.873 | 不该合 |
| 模板条目只差金额（100/120 元） | 0.826 | 0.789 | 不该合 |
| 问答题只差假别（年假/婚假） | 0.750 | 0.688 | 不该合 |
| 同章不同要点 | 0.000 | 0.000 | 不该合 |

真实语料上：≥0.72 有 15 对，≥0.85 有 7 对，≥0.90 有 **0** 对；≥0.85 的 7 对**全部**是 `neo4j建表细节.md` 里的 `CREATE CONSTRAINT` 代码块，只差一个 label。也就是说，在真实数据上**一个真重复都没有，15 对全是误合候选**。

结论有两条：

1. **该合的（0.92～1.00）和不该合的（0.69～0.87）区间重叠**，单一阈值分不开。`0.72` 会把模板条目和代码块一起合掉；`0.90` 又合不掉改过几个字的真重复。所以 3.3 那条「0.72 偏松」在这里得到量化：方向不是调阈值，是**加归一化 + 加护栏 + 把阈值提到 0.85**。
2. **"更聪明的字符法"更差**：`difflib.SequenceMatcher` 给模板句 0.935、给真重复 0.927（顺序颠倒）；`zlib` 的 NCD 给模板 0.880、真重复 0.837（同样颠倒）。原因是它们对「标点/空白改写」的惩罚比「改几个数字」更重。二字/三字组合已经是字符法里最好的。

护栏实测：抽出两条正文的数字串与 ASCII 标识符做多重集比较，不同就不合并——真实语料 15/15 误合对被拦下，真重复不受影响；唯一漏的是「年假/婚假」这种纯中文换词、无数字无英文的模板句，那种靠 0.85 阈值挡（0.688 < 0.85）。

### 6.2 精排模型能不能去重

能算，但不该放在在线链路上：

- **判的是相关性不是等价性。** cross-encoder 的训练目标是「这段文字能否回答这个问题」。两条都在回答「差旅费怎么报」的不同段落会双高，高分只说明各自和问题相关，不说明彼此重复；它的分数没有「等价」的校准线。
- **O(n²) 且不可批。** 现在 1 次调用排 20 条；两两比是 20 次调用（每次 19 个 document），和 `_TIMEOUT = 3.0` 的预算直接冲突，单次问答从 1 秒级涨到数秒。
- **非确定性 + 计费 + 进账本。** 把一个纯本地可回归的步骤换成外部依赖。

正确用法是**离线标定**：拿 100 对真实候选让精排/LLM 判「该合/不该合」，做 ground truth 定阈值和护栏。needs 2.2 说「这期不做一次新的嵌入调用」指的是线上，离线标定不冲突。

### 6.3 开源方案的定位

成熟的开源去重都是**语料级离线**工具，和本期「20 条候选、在线、单请求」不是一个问题：

| 库 | 层次 | 定位 | 能不能直接用于本期 |
|---|---|---|---|
| `datasketch` | MinHash + LSH | 近似去重的底层库，被大量项目引用 | 不能。n=20 时 LSH 无收益，还引入估计误差 |
| `ChenghaoMou/text-dedup` | MinHash / SimHash / 后缀数组 / Bloom | 一体化脚本，TOML 配置；作者已声明「不是通用库，建议 fork 而不是依赖」 | 只能当参考实现 |
| `huggingface/datatrove` | MinHash + 句级 | FineWeb 的管线，Slurm/Ray 分布式 | 不能。参数是 word 5-gram、默认目标 ≈72% Jaccard，中文没有空格，照搬会把「报销标准」这类术语切碎 |
| `NVIDIA/NeMo-Curator` | exact / fuzzy / semantic 三层，GPU + Ray | 十亿级语料 | 不能，量级不匹配 |
| `minishlab/semhash` | 语义（model2vec + Vicinity），MIT | 没有向量时快速建向量再做语义去重，毫秒级 | 用不上核心价值——向量已经在 Milvus 里 |
| `rapidfuzz` | 短文本模糊匹配（C++） | `process.cdist` 一次算 190 对 | 只解决速度，不解决语义，本期 190 对本来就微秒级 |
| **MMR**（LangChain `MMRRetriever`、FAISS/Chroma 内置） | 检索侧多样性重排 | 逐条选「相关性高且和已选差异大」的，`λ` 调权衡 | **范式对得上**：plan 的方案本质是「硬阈值版 MMR」；Milvus 无内置 MMR，要自己写约 30 行 |

值得注意的是：`datatrove` 的默认目标就是 ≈72% Jaccard、`text-dedup` 示例是 `threshold = 0.7`。plan_v14 的 `0.72` 很可能就是从这里借的——但那是**整篇网页**的尺度，不是 480 字的块，也不是中文。这解释了为什么照搬会偏松。

### 6.4 可以白拿的三样东西

1. **归一化**。`datatrove` 的 `TextNormConfig` 就是这个思路。实测：只留汉字/字母/数字（去空白 + 全部标点），长块真重复从 0.89～0.92 直接到 1.00，误合区整体左移。这是性价比最高的一行代码。
2. **removal log**。各家的共同要求是「每层都要写清楚删了谁、什么分、被谁删」。对应到本期：`kb_diversify` span 现在只输出留下的 `chunk_id`（plan §五 step 3），**被丢的那几条和触发分数没有留痕**，线上答案变差时查不出原因。建议输出 `留下=... 丢掉=id:score,...`。
3. **熔断**。三家的管线都要求「某层删得超过 sanity 阈值就停下报错，而不是静默继续」。对应到本期：收敛一次删掉超过 4 条（候选的 20%）就 `log.warning` 并退回 `hits[:KB_SEARCH_LIMIT]`，防止阈值配错一口气把 6 条砍成 1 条。

### 6.5 本期落地参数（建议写进 plan）

| 项 | plan_v14 现值 | 建议 |
|---|---|---|
| 归一化 | 只 `strip()` | 只留汉字/字母/数字（`ch.isalnum()`），去空白 + 全部标点 |
| 阈值 | `0.72` | `0.85` |
| 护栏 | 无 | 数字串 + ASCII 标识符多重集不同 → 不合并 |
| 短块 | 不足 2 字特殊处理 | `clean` 后不足 30 字不参与合并（`doc_kind=qa` 一问答一块，是误合重灾区） |
| 比较窗口 | 前 500 字 | 全文（块本来就 ≤480 字，不必和 `KB_CHUNK_CHARS` 耦合） |
| span 输出 | 留下的 `chunk_id` | 留下的 + 丢掉的 `chunk_id:score` |
| 熔断 | 无 | 删掉 >20% 候选时告警并退回排序后的前 N 条 |

二期若要认「换说法」的释义：不要引新模型，直接在 Milvus 检索时 `output_fields` 加上 `dense`（`kb/milvus.py:145` 现在没取），只在 `block_kind != "image"` 的行之间算余弦（图片行是图像向量，needs 2.2 的顾虑成立），只对 0.80～0.90 灰区做二次判定。代价是每条约 10KB 向量、20 条约 200KB 请求体，内网可接受。
