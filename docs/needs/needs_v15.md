## 一、需求简述
```
1. 文本提问收敛之后，给留下的每一条补上同一篇、同一章节里紧挨着的前一块和后一块；
   1.1 向量和关键词仍然只召回原来的大约 20 条，不把召回放大到 60 条；
   1.2 补相邻块是按入库顺序读编号，不是再用问题搜一次；
2. 相邻块只交给模型和参考来源，不参与精排，也不参与近义收敛；
3. 图片提问、离线召回评测不补相邻块。
```


## 二、需求详述

> 性质：这是**需求文档**（对照现有切块、召回和生成），不是实施方案。方案留给 plan_v15。
> 范围：只动企业知识库文本提问交给生成的那一组结果。食疗问答、实体链接、长期记忆、联网检索、图片入库、嵌入模型和 Milvus 集合不在本需求里。
> 第三节要拍板的都已定。

### 2.0 结论

长正文按大约 480 字切开，断开在句子之间。后一块常常是前一块的例外、限定或下一句。检索只拿每一块自己的正文去做向量和关键词，后一块若全是「以上」「不适用」这类指代，打不中问题，近义收敛也看不到它。模型只拿到前一块时，会把没有例外的半句当成完整规定。

行业里有两种补法。一种在入库时把相邻正文抄进同一行（句子窗口），检索一次就带出来。一种先召回，再按文档顺序把相邻块读出来。抄进同一行要改集合、重嵌，同一段正文存多份，窗口大小一变就要整篇重写。本库已经有 PostgreSQL 里的块正文，第二次按编号读取即可。

本期用第二种：

1. **召回条数不变。** 文本提问仍先取大约 20 条，精排后近义收敛成最多 `KB_SEARCH_LIMIT`（默认 6）条。不为了邻居把 Milvus 的 `limit` 改成 60。
2. **收敛之后按顺序补。** 对留下的每一条，读同一篇文档里序号减一和加一的块。序号是入库时按阅读顺序写下的，不靠页码临时排序。
3. **只补同一章节里紧挨着的块。** `heading_path` 不同的不补。例外句和它限定的那句都在一次 480 字切开的同一节里；上一节的最后一块不跟着进来。
4. **补到的块跟命中块排在一起交给模型。** 顺序是前一块、命中块、后一块。两条命中的邻居重叠时，同一 `chunk_id` 只出现一次。
5. **评测和图片提问不走这一步。** `search_question` 的返回仍是图片路径去重之后的候选。离线 Recall 的分母不变。

### 2.1 和现有链路的关系

| 步骤 | 现在 | 本期 |
|---|---|---|
| 混合检索 | 文本提问大约 20 条 | 不动 |
| 图片路径去重 | 同一 `image_path` 留一条 | 不动 |
| 精排、近义收敛 | 收成最多 6 条 | 不动，仍只看这 20 条 |
| 相邻块 | 无 | 收敛之后按序号读取，再送给生成 |
| 图片提问 | 最多 6 条，不精排不收敛 | 仍不补相邻块 |

邻居如果先放进那 20 条，精排和二字收敛会把它们当成新的命中。指代句和上一块用词不同，收敛丢不掉，名额却被占掉。所以邻居不进入精排，也不进入收敛。

### 2.2 怎样确定「相邻」

阅读顺序在写入 `kb_chunk` 时编成从 0 开始的序号。文本行、图像行、描述行按当时的入库顺序各占一个序号。PostgreSQL 不保证没有 `ORDER BY` 时的返回顺序，块 id 又是随机的，不能靠 id 或物理行号认前后。

Markdown 和 Word 没有页码和坐标，PDF 里也有坐标为空的图。不能只用 `page_no` 和 `bbox` 排序。

同一张图的图像行和描述行序号紧挨着，正文相同。命中其中一行时，另一行不再当作邻居，避免同一段描述出现两次。

文档第一块没有前一块，最后一块没有后一块，缺的那一侧不补。

### 2.3 旧文档

已经入库的块没有序号。本期不为此整库重嵌，也不重跑离线评测文档。这些块被命中时不补邻居，回答仍是现在的最多 6 条。重新通过或整篇重嵌之后，新写入的序号才参与相邻补齐。

### 2.4 接口上看见什么

相邻块进入生成提示，也进入接口返回的 `hits`，这样模型引用的章节和参考来源对得上。它们带 `neighbor: true`，不写检索分，不占 `KB_SEARCH_LIMIT` 的 6 个名额。

一条命中最多带出两块。6 条命中、邻居互不重叠时，交给模型的最多 18 块。前台插图规则不改：邻居若自己有图，仍按章节放进对应条目。

### 2.5 不做什么

不把相邻正文抄进 Milvus 的同一行。不改嵌入模型，不改 480 字切块，不改集合，不重嵌全库。不把同一章节的全部块都交给模型。不改图片路径去重、精排和近义收敛的规则。


## 三、需求补充

> 下面四项已拍板，施工口径以第二节为准。

### 3.1 相邻块跨不跨章节

按整篇文档的序号，前一块可能是上一节的结尾。那一节和当前问题无关，补进来会把两节的规定写进同一次回答。

**建议**：序号相邻，并且 `heading_path` 相同，才补。

按照建议。

**已拍板**：不跨章节。

### 3.2 没有序号的旧块要不要补

给旧块补序号必须重新解析并重嵌，块 id 会变，已有评测对照会失效。

**建议**：序号为空就不补邻居。要相邻块的文档单独重嵌，不在本期全库执行。

按照建议。

**已拍板**：旧数据不补，不全库重嵌。

### 3.3 相邻块算不算检索命中

只写进提示、不放进 `hits`，参考来源里看不到模型用到的例外句。放进 `hits` 又不能冒充它被问题和向量搜中。

**建议**：放进 `hits`，用 `neighbor: true` 标出，不填检索分，不占 6 条名额。

按照建议。

**已拍板**：返回给前台，并标明是相邻块。

### 3.4 图片提问和评测补不补

图片提问走图像向量，没有「后一句推翻前一句」这条文本链路。评测要的是召回集合，补邻居会把没被搜中的块算进命中。

**建议**：两条都不补。

按照建议。

**已拍板**：只加在文本提问的问答链路上，放在近义收敛之后。
