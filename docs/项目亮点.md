# 项目亮点

> 这些是代码里已经落地的选择，用来说明这套食疗助手和「文档切块 + 向量检索 + 直接生成」差在哪里。细节与阈值见 [技术细节.md](技术细节.md)，路径见 [数据流程.md](数据流程.md)。

## 1. 证据是两层，检索按层取舍

每条边同时有 `evidence_type`（guideline / measured / traditional / anecdotal）和 `evidence_level`（A / B / C / D）。类型决定这次意图能不能看见它，等级决定排序和回答档位。

「不宜同食」默认把 anecdotal 放进来，因为这类问题的主体就是民间说法；人群禁忌、药物相互作用、营养含量只放 guideline 和 measured。同一道菜上的两种说法不会被揉成一条「禁忌」边。

生成按档说话：有 A/B 就引用；只有 C/D 必须标明未经验证；没有命中就固定弃答。评估把这三档拆开打分，弃答正确率不和 faithfulness 混成一个数。README 记录的分层基线是 faithfulness 0.697、弃答 1.0、未收录处理 0.80。

## 2. 单源数据降级引用，而不是藏起来或当成硬证据

USDA 一条来源时，一致性分固定 0.6，总分约 0.88，低于自动通过线 0.9，并且来源数也不满足「至少两源」。抓取结果一律进人工。

人通过之后，边打上 `provisional`，证据等级封顶 C，上下文写成 `[measured/C·单源]`，回答前缀说明「已人工审核、未做多源交叉验证」。提示词禁止把这类实测值说成民间传言。

默认仍能查到。若审核通过的食材在问答里消失，用户会以为还没收录，再登记一次，队列会被自己人刷厚。需要只答硬证据时把 `INCLUDE_PROVISIONAL` 设为 false，Cypher 条件会排除这些边。严格模式和降级引用是两个开关，不是同一种隐藏。

provisional 节点不写 Milvus。向量兜底否则会绕开 Cypher 上的 provisional 过滤。

## 3. 主图只有一个写入口

抓取产物和 Excel 行都先变成 `kg_food_bundle`，审核只负责翻译成 `kg_node_candidate` 和 `kg_candidate`。写 Neo4j 的是 `kg.merge`：先节点、后边，关系用 `relation_key` 做确定性 MERGE，边上带 `batch_id`。

因此可以回答「这条边是哪一批、谁审核的」，也可以 `kg.merge --rollback bundle:3` 删掉该批的边，以及 `provenance` 标了该批的新节点。挂到已有食材上的补录不会把种子节点删掉。共享营养素不写 `provenance`，避免回滚时误伤其他食材。

表格导入曾经考虑过单独的演示表。迁移 013 把那张表去掉，导入和 USDA 走同一条审核链，问答和图探索看到的是同一张主图。

## 4. 同名异物靠词表，不靠食品分类

「黑豆」在 USDA 里容易对上黑菜豆。两者同属豆类分类，SR Legacy 还经常没有学名，用类别判断会选错物种，然后把错误的蛋白质数字写进图。

检索画像给出 `identity_keywords`（描述里必须出现，黑豆是 `soybean`）和 `exclude_keywords`（出现即否决）。模型即使把中文翻成 black beans，`soybean` 这一条仍会挡住 “Beans, black, mature seeds, raw”。

打分不用第二个模型给自己打 0.9。完整性、权威性白名单、来源数、是否和已有别名冲突，都是可重算的规则。权威来源目前只认 `usda_fdc` 和 `china_fcd`。

## 5. 口语到节点是数据表，不是问句上的 if-else

`dict_alias` 把「西红柿 / 番茄」、症状口语、人群说法收成 `canonical_id`。整句用最长匹配切词，避免「凉拌黑木耳」被短别名「木耳」切碎。

中文相似度用字级包含和编辑距离。`pg_trgm` 对「黑大豆」和「黑豆」给出 0，所以中文主路径不走它。

对不上的词先做近似：像已有食材就写入别名候选并反问，而不是立刻新建节点。复合词先收到中心词，黑豆粥、炒黑豆、凉拌黑豆共用一条抓取任务和一个 `hit_count`。

未收录时的回答是登记函数拼出来的，不经过生成模型，因此不会在「库里没有」的时候编出营养表。

## 6. 知道的食材和不知道的食材，弃答不是同一句话

图没有边、向量也没有块时：

- 食材已经链上：说明收录了，但没有能回答这个问题的证据，不凭常识推测。
- 什么都没链上：说明没有找到确切依据。

前一种若不区分，用户会再次登记，把已在图里的食材又送进抓取队列。

红旗症状（胸痛、呕血、意识模糊等）在查图之前结束，直接建议就医。免责声明随每条回答卡片下发。

## 7. 用户约束进查询，不进模型的「请注意」

过敏和忌口从 `user_profile` 读出，作为 Cypher 参数排除搭配、相克、替代的对端食材。模型看不到已经被滤掉的行，也就无法把过敏原推荐回去。

短期对话只放进提示词帮助指代，系统提示写明不能当成图谱事实。用户拒绝采集时，本轮不读不写画像。

匿名身份由服务端签发。登录时把该匿名 id 下的会话和画像改挂到手机号账号，避免「我海鲜过敏」在登录后消失。匿名 id 若改成前端自填，就可以把别人的过敏史并进自己的账号。

## 8. 模型是池，不是配置里的一个名字

额度用尽的模型移出池并落盘，重启不会再去撞它。限流和 5xx 冷却后自动回来。401/400 不切换，免得用错误的密钥把池打空。池空了用 `LLM_MODEL` 兜底；兜底也失败就告诉用户暂时答不了。

切换走 LangChain 的 `wrap_model_call`，业务代码调用 `invoke_model`。推理模型把 token 预算花在思维链、正文为空时，自动把上限抬高再试一次。

## 9. 登录把短信轰炸和令牌重放分开处理

手机号以 HMAC 做唯一索引，Fernet 保存可还原密文，界面只看到掩码。验证码失败：同一号码 5 次锁 15 分钟；同一出口 IP 要 50 次才锁，避免办公室 NAT 后面的人互相锁死。

发送侧是同号、同 IP、同设备再加全站每天 200 条熔断。同一 IP 免费发码次数用完后要图形验证码。平台短信接口不管「拿别人的号码刷」，这层在自己的日志表上。

refresh token 只存哈希。旋转后的旧票再出现会吊销整条 family。用户主动登出的吊销不走这条重放逻辑，下次登录不会被提示成异常登录。

## 10. 图可以画出来，而且和回答用的是同一批行

问答返回的 `subgraph` 由当次 Cypher 行翻译，不另查一次库，所以画面上的边和模型看见的事实一致，并带证据等级和单源标记。历史消息把这张卡片存进 `meta`，回放不用重新生成。

探索接口可以展开邻域或找两食材的最短路径（例如都含某种营养素），点数和跳数有上限，避免一次拉出整张图。

## 11. 评估和追踪按「有没有走图谱」切片

Langfuse 的 trace metadata 带 `graph_hit` 和证据等级计数，可以单独看降级到文档的那些问句。Ragas 只跑有据样本；弃答和未收录用确定性规则，不把「有没有编造数字」交给另一个模型。

抓取、打分、合并、回滚都在请求之外，问答延迟不包含 USDA 的十几秒，建库动作也留得下任务状态和预算。
