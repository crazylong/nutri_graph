# 「养生了么」上架合规手册

> 目标：把本项目注册为「养生了么」产品并发布到应用市场。
> 性质定位：**健康/医疗信息类 APP（食疗科普问答）** —— 这是合规门槛最高的一档，不是普通工具类。
> 本手册是**自查清单 + 行动路线**，不构成法律意见。商标、医疗合规、数据合规涉及专业判断，最终建议找专业机构复核。

---

## 〇、先定性的红线（读这一节就能避最大的坑）

本项目用知识图谱约束 LLM 输出食疗建议、禁忌、营养素，在监管口径下接近「互联网医疗 / 健康管理」服务。三条铁律：

1. **不碰「诊疗」**：全站文案禁止出现「治疗 / 治愈 / 根治 / 处方 / 诊断 / 疗效」等词。食疗建议一旦涉及具体疾病治疗，就落入《医疗广告管理办法》和互联网诊疗监管，需医疗机构资质（无资质主体做不了）。
2. **不做疗效断言**：项目已有的「无据弃答」「provisional 降级引用」「不做疗效断言」设计方向正确，必须持续强化——这是合规护城河。
3. **敏感个人信息单独同意**：用户输入的「失眠 / 生理期 / 过敏」等属于敏感个人信息，收集需**单独弹窗授权** + 必要性说明，不能混在一般条款里。

---

## 一、品牌合规（商标）

### 判断
- 「养生了么」整体可尝试注册，但 **「了么」词尾显著性弱**，国内「XX了么」类商标极多，注册时大概率被驳回「缺乏显著性」或与他人近似。
- 「养生」是**通用行业词**，只对「养生了么」整体组合有权利，别人仍可用「养生」二字。

### 自查项（勾选）
- [ ] 做商标近似检索（国家知识产权局商标网 / 权大师 / 白兔等），重点类别：
  - [ ] **44类**（医疗保健/养生服务，核心）
  - [ ] **9类**（APP 软件）
  - [ ] **42类**（软件/SaaS）
  - [ ] **35类**（电商/广告推广）
  - [ ] **38类**（信息传送/社群）
- [ ] 同步查域名 / 公众号 / 小程序名是否被占用
- [ ] 若「养生了么」因缺显被驳回，准备备选方案（避开「了么」后缀，或加图形/设计元素增强显著性）

## 二、主体资质（注册个体户）

### 判断
个体户能跑通大部分前置流程（商标/ICP/App备案/软著），但**健康类目上架是最大变数**——多数应用市场对健康/医疗类要求**企业主体**，个体户大概率被拒，或只能以「资讯/工具」类上。

| 环节 | 个体户 | 说明 |
|---|---|---|
| 商标注册 | ✅ | 可办，缺显问题仍在 |
| ICP 备案 | ✅ | 可办 |
| App 备案 | ✅ | 可办 |
| 软著登记 | ✅ | 可办 |
| 算法备案（生成式AI） | ⚠️ | 能备，审核更严 |
| 健康类上架审核 | ❌ | 多数市场要求企业主体 |
| 食品/商城变现 | ❌ | 需食品经营许可，范围窄 |

> 建议：先个体户跑通验证，真到健康类目上架时再升公司（公司可用园区虚拟地址，反而省场地）。

### 注册流程
1. **确定登记信息**：经营者（本人）、名称（`XX市XX区养生了么信息咨询服务部`，准备 2-3 个备选名）、经营范围。
2. **线上登记**：当地政务服务网 / 市场监管「一网通办」/ 支付宝「企业开办」，实名认证 → 名称申报 → 填信息 → 电子签名 → 提交。
3. **经营场所**：自有住宅需「住改商」证明；租房需合同+房产证；或集群/托管地址（需确认覆盖经营范围）。
4. **领照+后续**：营业执照 → 刻章 → 税务登记（可申请定期定额核定征收）→ 对公账户 → 每年 1-6 月年报。

### 建议经营范围（直接抄）
```
一般项目：健康咨询服务（不含诊疗服务）；信息咨询服务（不含许可类信息咨询服务）；
互联网信息服务；软件开发；食品销售（仅销售预包装食品）；会议及展览服务。
```
> 明确**不写**：医疗服务、诊疗服务、药品零售、保健食品销售（除非后续真做并拿对应许可）。

### 时间与成本
- 全程线上，3-7 个工作日拿执照；登记免费，刻章多数地方免费。
- 唯一潜在花费：经营场所（租场地或托管地址，几百到几千/年）。

## 四、数据合规（《个保法》《数安法》）

项目安全设计已较扎实（phone_hash/enc/mask 三态、四维频控、refresh 旋转、注销、匿名归并），上架还差：

- [ ] **隐私政策明示**收集范围、用途、第三方 SDK 清单（阿里云 dypns 短信、DashScope、Milvus、Langfuse 等都要披露）

- [ ] **数据出境评估**：确认 Milvus/DashScope 等是否有境外节点或数据出境，若有需安全评估

- [ ] 未成年人保护条款（健康类尤其敏感）

## 六、行动路线（按性价比排序）

1. **【立即，零成本】** 全站文案加免责声明，清除「治疗/根治/功效」类表述（文案见附录 A/B）。
2. **【商标】** 做一次近似检索，确认「养生了么」能否注册；不能就换名。
3. **【主体】** 注册个体户（或直接公司），这是后面所有备案/软著/上架的前提。
4. **【备案链】** 域名 ICP → App 备案 → 算法备案 → 软著。
5. **【隐私合规】** 补敏感信息单独同意，隐私政策列全第三方 SDK。

## 附录 B：隐私政策要点（敏感信息单独同意）

> 完整隐私政策建议找专业法务/模板工具生成，以下是**必须覆盖的关键条款骨架**，尤其突出本项目特有的敏感信息场景。

### 收集信息清单（明示 + 用途 + 第三方）
| 信息 | 用途 | 是否敏感 |
|---|---|---|
| 手机号 | 登录注册、账号标识 | 否（但需脱敏存储） |
| 聊天提问内容 | 生成回答、改进服务 | 是（可能含健康信息） |
| 用户特征（年龄/性别/症状/过敏等） | 长期记忆、个性化回答 | **是（敏感个人信息）** |
| 设备/IP | 安全频控、防刷 | 否 |

### 敏感个人信息单独同意（弹窗文案）
```
「养生了么」为提供更贴合您情况的饮食建议，需要收集并存储您的健康相关信息
（如症状、过敏史、生理期等）。这些信息属于敏感个人信息，仅在您明确同意后
收集，且仅用于为您提供个性化服务。

[ 同意收集健康相关信息 ]   [ 拒绝，仅提供通用回答 ]
```
> 拒绝时产品仍可用（降级为不提取个人特征），这是合规关键——不能「不同意就不让用」。

### 第三方 SDK 披露清单
| SDK/服务 | 用途 | 涉及信息 |
|---|---|---|
| 阿里云 dypns（号码认证） | 短信验证码登录 | 手机号 |
| DashScope（百炼） | LLM 问答生成 | 提问内容 |
| Milvus | 向量检索 | 提问向量 |
| Langfuse | 可观测性/追踪 | 调用日志 |

### 用户权利
- 查询、更正、删除个人信息
- 注销账号（已实现 `/auth/me` DELETE，需前端提供入口）
- 撤回同意

### 未成年人
- 原则上不面向未成年人提供服务，若涉及需监护人同意。
